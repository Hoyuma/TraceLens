## 判断したこと

1. **構成は推奨どおり**（MV3 / TypeScript / React / Vite / サイドパネル / 独立タブのレビュー画面 / IndexedDB / ローカル ZIP）。Vite はプラグインを使わず、ページ＋Service Worker（ESM）とコンテンツスクリプト（単一 IIFE）の 2 回ビルドにした（依存を減らし、注入スクリプトを 1 ファイルにするため）。
2. **権限は `activeTab` を基本にした。** `captureVisibleTab` の要件上、選択肢は `activeTab` か `<all_urls>` しかない。インストール時に全サイトへのアクセスを求めるのは「通常の記録に不要な強い権限」に当たると判断し、`<all_urls>` は任意（`optional_host_permissions`、パネルから明示的に許可）とした。代償として、別オリジンへの遷移で記録が中断する。中断は通知ステップとパネル表示で明示し、アイコンのクリックかショートカットで再開できる。
3. **コンテンツスクリプトはマニフェストに登録せず、記録対象タブにだけ都度注入する。** 他のタブには一切スクリプトが入らない。
4. **パネルを開く操作と権限付与を同じクリックにまとめた**（`action.onClicked` で `sidePanel.open()`）。`openPanelOnActionClick` は使っていない。
5. **`tabs` / `webNavigation` / `debugger` / `downloads` 権限は使わない。** ページ遷移は対象タブの `tabs.onUpdated` とコンテンツスクリプトの再接続で検出し、SPA の URL 変更はページ内（Navigation API・`popstate`・`hashchange`・定期確認）で検出する。ZIP の保存はリンクのクリックで行う。
6. **画面取得のタイミング**: 操作後、DOM 変化が 400ms 止まった時点（最長 2.5 秒）で取得する。その後も次の操作か約 8 秒までは観測を続け、変化があれば静止のたびに取り直す（1 手順あたり最大 3 回、最後のものを保持）。静止前に次の操作が始まった場合はその時点で取得し、「次の操作の影響が写っている可能性がある」と画像に注記する。ページ遷移で失われた場合は取得せず、理由を残す（遷移後の画面を流用しない）。
7. **操作位置の強調**は、画像取得の直前に対象要素の位置を測り直せた場合だけ表示する。要素が消えた・表示領域外・クロスオリジンフレーム内の場合は表示しない。
8. **DOM は操作時点（ページ側の処理が走る前）に取得する。** 画面は操作後、DOM は操作時点と、意味が異なることを `phase` で区別している。次の手順の DOM が実質的に「操作後」の構造になる。script / style の中身は保存しない。iframe の中身は親の DOM に展開せず、フレーム内で操作があったときにそのフレームの DOM を保存する。
9. **クリックの重複を避ける**: チェックボックス・ラジオ・select は値の変化として記録し、クリックとしては記録しない。編集可能な入力欄へのクリック（フォーカス移動）と、入力欄に紐づく label のクリックも記録しない。
10. **入力の集約**: 同じ欄への編集は、フォーカスが外れる・別の操作が起きる・Enter / Tab などが押される・ページを離れるまで 1 手順にまとめる。IME の変換中のキーは操作として扱わない。日付・数値系の欄は 1 キーごとに `change` が発火するため、フォーカスが外れた時に確定する。
11. **機密欄**: `type="password"` と、`autocomplete` が password / one-time-code / クレジットカード系の欄は値を読まない。「パスワードを表示」で `type="text"` に切り替わった後も機密として扱う。
12. **記録するキー**: Enter、Tab、Escape、ファンクションキー、修飾キーつきの組み合わせ（コピー・貼り付け・全選択・元に戻すを除く）。矢印キー等は、リストボックスなどのウィジェット上でのみ記録する。
13. **セレクターの安定性**は `unverified`（未検証）と `suspect`（動的生成・位置依存の疑い）の 2 値のみとし、「安定」とは表記しない。
14. **グループ化**: 当初は手順へのグループ名の付与と範囲指定のみだった。2026-11-17 に、入れ子（循環の検査つき）、名前変更、削除（子グループと手順は親へ繰り上げ）、手順とグループのドラッグによる移動を実装した。順序（`seq`）は変えない。
15. **同時に記録できるのは 1 セッション**。
16-a. **ページ全体の画像**は `debugger` を使わず、コンテンツスクリプトがウィンドウのスクロール位置を順に動かし、Service Worker が各位置で `captureVisibleTab`（既存の間隔制御）して OffscreenCanvas で 1 枚に合成する。上限は 15 枚・高さ 16000 デバイス px・合計 4800 万画素で、超えたら途中までであることを `reason`・`limitations`・`captureInfo.partial` に残す。取得中に文書・対象タブ・前面状態が変わった、スクロール位置が合わなかった、ユーザー操作（ホイール・キー・クリック）があった場合は破棄して理由つきの未取得にする。終了時は必ず元のスクロール位置へ戻す。TraceLens が起こしたスクロールは `isTrusted` でないため操作として記録しない。固定ヘッダーの重複・遅延読み込み・スクロールで変化する内容は実際の見た目と一致しないことがあり、`captureInfo.notes` に記録する。ウィンドウ自体がスクロールしないページ（内部の overflow 領域）は対象外。
16-b. **要素単位の画像**は、要素選択で選んだ要素の矩形で、取得した表示領域の画像を切り出す。取得直前と直後に位置を測り直して一致した場合だけ切り出し、確認できなければ理由つきの未取得にする（別の場所を切り出さない）。要素が表示領域に収まらない場合は、スクロール合成は使わず、見えている部分だけを切り出して `captureInfo.elementClipped` と `limitations` に記録する（スクロールでページの状態を変えない判断）。切り出した画像・合成画像には操作位置の強調を出さない（`targetRectAtCapture: null`）。画像は `shot_<stepId>` の 1 手順 1 画像の枠に入れ、`Artifact.captureInfo` に取得方法を持つ。合成画像の `timingNote` は、レビュー画面に注意を出すために合成の注意を載せている。
16-c. **操作前の画面**は、新しい画像を作らず、直前に取得した表示領域の画像を参照する（`Step.beforeScreenshot`、`basis: 'previous-observation'`）。画像の取得開始以降に、DOM の変化・スクロール・リサイズを観測していない（各フレームのコンテンツスクリプトが時刻だけを SW に通知）、同一文書、同一ビューポート・スクロール位置、のときだけ参照する。条件を満たさなければ `skipped` と理由コード。「観測の範囲で変化なし」であり画面が同一である保証ではない（:hover・アニメーション・動画・canvas・観測できないフレームなどは分からない）。表記は「直前の観測時点の画面を参照」とし、「操作直前に取得した画像」とは書かない。設定は既定で無効（`chrome.storage.local`）で、記録開始時の値を使う。
16-d. **新規タブ・別ウィンドウ**は、設定が有効なとき、対象タブから開かれたタブ（`openerTabId`）へ記録対象を**切り替える**（同時に 2 タブは記録しない）。前後に通知の手順を残し、`docEpoch` を上げ、保留中の成果物を確定する。切り替え前のタブは `tabStack` に積み、切り替え先が閉じられたら残っている元のタブへ戻る（戻れなければ通知して終了）。新しいタブには `activeTab` が効かないため、`<all_urls>` かそのオリジンの権限がある場合だけ切り替え、ない場合は通知を残して「保留」にし、そのタブでアイコンをクリックして `activeTab` が付与されたら切り替える。切り替え前のタブの確定済み手順への追記（入力の確定など）は受け付ける。
16. E2E 用に `sidepanel.html?tabId=…` で対象タブを指定できるようにした（別ウィンドウでパネルを開く用途。通常利用では不要）。
17. **自動再生の範囲に入れた判断**（2026-11-17、リポジトリ管理者の指示）: 目的は、記録したシナリオが妥当かを再生で確かめながら調整し、AI に渡す資料の精度を上げること。副次的に、定常業務の試験的な自動化にも使える。再生は「確かめるための道具」であり、業務処理の完了や成功を保証しない（ok の意味は下記 24 を参照）。
18. **記録の事実と編集の層を分ける**: 記録された事実（`seq` `operationAt` など）は書き換えない。表示・再生の順序は `order`、再生設定は `replay`、由来は `origin` として、別の層に持つ。
19. **手順の削除は物理削除**（確認つき。元に戻せない旨を表示する）。出力対象から外すだけの場合は、チェックを外す手段を使う。残りの手順の `seq` は変えない。
20. **データ形式**: `SCHEMA_VERSION` 2、IndexedDB の `DB_VERSION` 2。追加した項目はすべて省略可能で、v1 のレコードと v1 の ZIP を読める。DB の移行は `replayRuns` ストアを追加するだけで、既存のレコードは変えない。
21. **変数**は `{{名前}}` の書式とする。secret の変数は既定値も実行時の値も保存せず（Service Worker のメモリのみ）、失われた場合は再入力を求める。
22. **機密欄**は、再生でも値を書き込まず、人が入力する。
23. **再生は `debugger` を使わない**ため、再生の操作は `isTrusted` でないイベントになる。信頼されたイベントだけに反応するページでは効かない（既知の制限を参照）。記録用スクリプトは、これらの再生由来のイベントを記録しない。
24. **再生の「ok」の意味**: 「操作を実行し、待機条件を観測できた」。`completed` は最後まで実行したことを示し、業務処理の完了は確認していない。
25. **ホスト権限**: 再生は対象オリジンのホスト権限（任意権限）を使い、再生の開始時に UI から要求する。必須権限は増やしていない。
26. **遷移の扱い**: 操作による遷移は移動し直さず、`url-matches` などの待機条件で待つ（同じ遷移の二重発生を防ぐ）。
27. **二重操作の防止**: 操作の直前に Service Worker へ `replay:acted`（`attemptId`）で承認を取る。SW が再起動して操作済みと分かった場合は、やり直さずに止める。
28. **フレームの特定**: Service Worker が `frame.path` と照合して `frameId` を決める。
29. **dom-quiet の時間切れは失敗にしない**。画面変化が続いたことの観測であり、業務処理の完了を判定しないため。
30. **正規表現の置換**: 一致した具体的な値を集め、リテラルのルールに展開してから置換する（表記ゆれ・長い値の優先・残留検査をリテラルと同じにするため）。`replaceWith` の `$1` などは展開しない（置換前の値の一部を出力に戻さないため）。制限値（パターン 300 文字、一致 1,000 文字、一致の種類 2,000、入力 5,000,000 文字）はコード（`REGEX_RULE_LIMITS`）の値とする。
31. **取り込み**: 取り込んだ手順の時刻は `importedFrom` に移し、`operationAt` は取り込んだ時刻とする。取り込み元の観測時刻であることは `limitations` に残す。取り込んだ内容は検証しない（警告を出す）。
32. **再生時の変数の値は出力 ZIP に出さない**（`latestReplayRun` は変数名と、値が与えられたかだけを出す）。
33. **画像編集**: ぼかしはブロック平均＋ぼかしとし、元の画素を復元できない強さにする。切り抜きは範囲の画素だけから作り直し、範囲の外は出力に入れない。保存済みの原本は変えない。
34. **Accessible Name** は accname-1.2 と HTML-AAM の主要部分の独自実装であり、ブラウザの結果との一致は未検証。扱わない規則（CSS 生成内容 `::before` `::after`、closed Shadow DOM、`aria-describedby`、SVG の title / desc など）は `src/shared/accname.ts` のコメントに列挙する。
35. **記録中のシナリオ**には、手順の追加・取り込み・削除を行わない（採番が記録側と衝突するため）。記録と再生は同時に動かさない。
36. **操作の後の権限待ち・SW 再起動からの再開では、操作をやり直さない。** 操作済みの印（`ActiveReplay.actedResume`）がある手順は、再開時に待機条件の観測だけを行う（重複登録の防止）。印は `chrome.storage.session` に置くため、SW の再起動後も有効。
37. **操作済みの可能性がある失敗の再試行は、UI で警告と確認を挟む。** `acted` が `yes` / `possibly` の失敗は、再試行の前に「二重になるおそれがある」旨を表示し、確認を要求する。
38. **手順の実行中に停止した場合は「停止時に実行中」として残す。** `acted` に応じて、`no` は `skipped`、`yes` / `possibly` は `failed` とし、いずれも `stoppedWhileRunning` を付け、理由を書く。成功（ok）にも、未実行（pending）にもしない。
39. **記録した再読み込みは、「現在の URL へ GET で移動し直す」として再生する。** フォームの再送信（重複登録）を避けるため。URL の `#` 以降は外す。記録時の再読み込みと同じ動作ではない（`RELOAD_AS_GET_NOTE` を UI と結果に出す。既知の制限を参照）。現在のページが http(s) でなければ、記録時の URL を使う。
40. **権限の再許可は、実際に足りないオリジンを要求する。** 分からない場合（タブの URL が読めない）は任意権限 `<all_urls>` を要求し、その旨を案内する。必須権限は増やさない。
41. **再生の対象タブは、新しいタブか、URL が見える既存のタブのどちらか。** 既存のタブの候補は、tabs 権限なしで URL が見える（アクセスが許可された http(s) の）タブだけを出す。新しいタブで開始するには、計画の最初の手順が移動（navigate）である必要がある（それ以外は理由つきで開始しない）。既存のタブで開始するときは、そのタブのオリジンのアクセス権も同じ要求に含める。
42. **取り込んだ手順の「操作前の画面」の参照は付け替える。** 参照先が取り込み対象にあり画像をコピーできた場合だけ付け替え、できなければ理由つきの未取得にする（取り込み元の ID を残さない）。
43. **UI の多言語化は、日本語（既定）と英語。** 出力 ZIP、保存データ由来の文言（通知・理由・制限など）、ページ内の再生中表示（ページに出す文字列）は、言語設定にかかわらず日本語固定とする（AI に渡す資料の形式と、記録の文言を変えないため）。言語は `tracelens.settings` の `lang` に保存する。
44. **select の再生は、記録した選択肢の value か表示名が一致する選択肢だけを選ぶ（位置だけでは選ばない）。**（2026-11-17、実ブラウザ e2e の結果で変更）当初は value → 表示名 → 位置（index）の順で照合していたが、選択肢が遅れて差し替わる画面（模擬ページの工程候補）で、差し替え途中の別の候補一覧から同じ位置の別の値（`1000`）を選び、その直後に本来の候補へ差し替わって未選択になり、保存が必須エラーになった。位置だけでの照合は推測で値を補うことになるため廃止し、一致する選択肢が現れるまで上限時間まで待ち、現れなければ理由つきで失敗にする。

## 既知の制限

- 別オリジンへの遷移で権限が失効し、再許可までの操作は記録されない（上記 2）。
- ページ読み込みの開始から記録スクリプトの注入までの間（通常は短時間）の操作は記録されない。
- 新しいタブ・別ウィンドウへの記録継続は任意設定（既定は無効）。同時に記録するのは 1 タブだけで、切り替え前のタブの操作は記録されない。権限のないタブは、そのタブでアイコンをクリックするまで切り替わらない。ポップアップウィンドウのサイドパネルは、そのウィンドウでは自動では開かない。
- ページ全体の画像は、固定ヘッダーの重複・遅延読み込み・スクロールで変化する内容により実際の見た目と一致しないことがある。ウィンドウ自体がスクロールしないページ（内部のスクロール領域）は全体を取得できない。取得には数秒かかり、その間のユーザー操作があれば破棄する。上限を超えると途中まで。
- 要素単位の画像は、見えている部分だけ（表示領域外の部分は含まない）。矩形内に重なっている他の要素も写る。
- 操作前の画面の参照は、観測の範囲での判定であり、画面が同一である保証ではない。フレーム内の変化の通知は最大約 0.1 秒遅れる。SW が長時間ブロックされるとフレーム間の変化の取りこぼしがありうる。
- 画像は表示領域のみ。対象タブが背面・最小化のときは取得しない。
- クロスオリジン iframe は、アクセス権のあるフレームのみ記録する。`activeTab` だけの場合に別オリジンのフレームへ注入できるかは未確認。フレーム内の操作に伴う画面変化の観測は、そのフレーム内に限る。
- closed Shadow DOM の内部は取得できず、存在の検出もできない（カスタム要素には可能性を注記する）。canvas は位置のみ。
- ブラウザ内部ページ、拡張機能ストア、PDF ビューアなどは記録できない。
- role と名前は簡易推定の候補であり、完全な Accessible Name 計算ではない。
- ページ側のスクリプトが発生させたイベント（`isTrusted` が false）は記録しない。自動入力ツールによる入力も記録されない。
- ドラッグ＆ドロップ、ホバー、スクロール、右クリックメニュー、ファイルの内容、クリップボードの内容は記録しない。
- 3MB を超える DOM は後半を省略する（省略したことを記録する）。
- 画像内の文字は自動でマスクしない。
- 数字 1 文字などの短い置換は、無関係な箇所も置き換える（UI で警告）。置換後の残存検査は、ファイルサイズの数値などに偶然一致して警告を出すことがある。
- 記録データはブラウザのプロファイル内にあり、拡張機能を削除すると失われる。別 PC への移行機能はない（出力 ZIP の取り込みは可能）。
- 再生は `isTrusted` でないイベントを使うため、信頼されたイベントだけに反応するページでは効かない。
- 再生中に alert・confirm で止まると、ページから応答がなく、その手順は失敗になる。
- ファイル選択は再生できない（人が操作する手順になる）。
- クロスオリジンの iframe は、そのオリジンのアクセス権がある場合だけ再生できる。
- manual の手順の後は、待機条件を観測しない。
- 手順を削除しても、過去の再生結果には参照先のない `stepId` が残る（履歴として保持）。
- 正規表現の遅いパターンの判定は簡易で、すべての遅いパターンを防げるわけではない。
- 記録した再読み込みは、現在の URL へ GET で移動し直して再生する（[判断 39](#判断したこと)）。ブラウザの再読み込みとは異なり、フォームの送信内容（POST）や、再読み込みで変わる一時的な状態は再現しない。
- 操作の後に権限待ちで止まり、再開したときは操作をやり直さず待機条件の観測から続ける。その手順の操作が結果として 1 回だけ行われたことは、実ブラウザでは未確認。
- 失敗した手順の操作が実行されたかは、ページからの応答（`replay:acted`）と SW の記録で判定する。応答が届かない場合は「可能性がある」として扱い、確定しない（確認を挟む）。
- 手順の実行中に停止した場合、`acted` が `no` の手順は `skipped`（理由つき。`stoppedWhileRunning`）になる。「停止時に実行中」の表示は、そのまま履歴に残る。
- 再生で入力した値が、待機の後にページ側の処理で書き換えられた場合は検出できない。「ok」は操作の実行と待機条件の観測の結果であり、その後の値の確認ではない。

## 未実装項目・対象外

### 対象外のまま（原則に反するため）

- **AI API 連携、クラウド同期、認証、チーム共有**: 原則 4「外部へ送信しない」、原則 3「対象外の機能を足さない」と衝突する。
- **Selenium コード生成**: 原則 2「`src/` は自動化技術に依存しない」と衝突する。再生で確認したシナリオは、中立的な JSON / Markdown で出力する。コード化は受け取った側に任せる。
- **画像内文字の検出**: 外部ライブラリや外部通信なしに、信頼できる手段がない。目視で確認する注意を、UI と出力に表示する。

### 未実装（残り）

- 完全な Accessible Name / role 計算（簡易推定と、限定的な独自計算のみ）
- 多言語 UI のうち、日本語・英語以外の言語、出力 ZIP・保存データ由来の文言・ページ内表示の多言語化（出力は言語設定で形式を変えない方針のため日本語固定）
- 新規タブ・別ウィンドウへの記録継続のうち、アクセス権のないタブでの実ブラウザ検証（自動テスト用ビルドは権限を事前付与しているため未検証）

### 実装済み（2026-11-17 に未実装から移したもの）

- 自動再生、プロジェクト・シナリオ・手順の削除、プロジェクト名の変更、記録データの取り込み（別シナリオ・出力 ZIP）、グループの入れ子・名前変更・削除・ドラッグ、画像のぼかし・切り抜き、置換ルールの正規表現、操作前の画面の参照、ページ全体・要素単位の画像、新規タブへの記録継続（任意設定）。いずれも実ブラウザでの検証は未実施（[verification.md](verification.md) 参照）。
