## B. 実ブラウザでの通し検証（`npm run e2e`）— 63/63 項目成功

- ブラウザ: `Mozilla/5.0 (X11; Linux x86_64) AppleWebKit/537.36 (KHTML, like Gecko) HeadlessChrome/153.0.0.0 Safari/537.36`（ヘッドレス）
- 模擬業務ページに対して、パネルの UI を実際に操作して「記録 → レビュー → ZIP 出力」を実行し、保存データと出力 ZIP の中身を検査しています。
- **前提の違い（重要）**: ツールバーアイコンのクリックは自動化できないため、この検証は `host_permissions: <all_urls>` を付けたテスト用ビルド（`dist-e2e`）を使い、記録パネルをサイドパネルではなく別ウィンドウで開いています。配布用ビルドの権限まわりは C で別に確認しています。
- 日本語 IME は、CDP の `Input.imeSetComposition` / `Input.insertText` で変換途中のイベント列を再現したものです（実際の IME ソフトでの入力ではありません）。
- Service Worker の停止は、デバッグ用プロトコルで Service Worker を強制終了して再現しています。

## 検証で見つけて修正した不具合

| 不具合 | 修正 |
|---|---|
| 日付欄は 1 キーごとに `change` が発火し、入力が複数の手順に分かれる | 日付・数値系の欄はフォーカスが外れた時に確定 |
| Enter で確定した入力に、遅れて届く `change` で重複した手順ができる | 確定済みと同じ値の `change` を無視 |
| 最初の静止で観測を終えるため、「保存中…」の後の「保存しました」を取りこぼす | 次の操作か上限時間まで観測を継続し、画面を取り直す |
| 欄から欄へ続けて入力すると、操作後の画面がほとんど残らない | 次の操作の開始時点で取得し、その旨を注記 |
| 数字だけの値を置換すると、DOM で URL エンコード表記（`%7B%7B…`）に化ける | 置換表記の優先順位を修正 |
| レビュー画面の「出力に含める」（画像・DOM）のチェックを外しても反映されない | 値の読み取りタイミングを修正 |
| 数字で始まる ID のセレクターが要素に一致しない | 単純な識別子以外は属性セレクター（`[id="…"]`）で出力 |
| ビルド出力に特殊な文字が入り、Chrome がコンテンツスクリプトを読み込めない | 該当コードを削除 |
| 権限の再許可直後にショートカットで保存した画面が失敗する | スクリプトの準備を待ってから保存 |
| 別の場所で作成したプロジェクトが、開いたままのパネルの選択欄に出ない | 記録開始時とフォーカス時に再読込 |

## 未確認の項目

- Microsoft Edge、Google Chrome 安定版、Windows / macOS での動作全般
- サイドパネル内のボタンを人が直接操作する流れ（上記 C の制約）
- 実際の IME ソフト（Microsoft IME、Google 日本語入力など）での入力
- 実際の勤怠システム（テスト環境）での記録。SSO などで別ドメインを経由する場合の使い勝手
- 任意の「全サイトへのアクセス」を許可するダイアログの操作と、許可後の別オリジン遷移での継続
- クロスオリジン iframe 内の操作の記録（`activeTab` のみの場合に注入できるか）
- 大きなページ（DOM が数 MB）・長時間（数百手順）の記録での速度と保存容量
- 高 DPI ディスプレイ、ブラウザのズーム変更時の操作位置の強調表示のずれ
- 拡張機能の更新・再読み込みをまたいだ後の、記録中タブの挙動（中断として扱う処理は実装済みだが未検証）
- ダークモードの配色（定義はあるが目視確認していない）

## 実機での確認手順（Edge / Chrome）

1. `dist` を読み込み、TraceLens をピン留めする。
2. `npm run mock` の模擬ページを開き、アイコンをクリック → サイドパネルが開き、「記録対象タブ」にタイトルと URL が出ることを確認する。
3. [guide.md](guide.md) の手順どおりに記録 → レビュー → ZIP 出力を行う。
4. 普段使っている IME で作業メモを入力し、1 手順にまとまることを確認する。
5. 別オリジン（例: `http://localhost:4173/index.html`）へ移動し、「記録が中断しています」の表示と、アイコンのクリックでの再開を確認する。
6. Edge では、タブを切り替えて戻ったときにサイドバーが閉じていないかを確認する（公式ドキュメントに既知の問題の記載あり）。閉じていた場合は、アイコンをクリックすれば再度開く。
