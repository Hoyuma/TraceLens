# 最初の調査を行う操作ガイド

模擬業務ページを例に、記録から編集・再生・ZIP 出力までを一通り行う手順です。実際の業務システムでも流れは同じです。

## 0. 準備

1. `npm install` → `npm run build` → `dist` を Edge / Chrome に読み込み、TraceLens をツールバーにピン留めする（[README](../README.md) 参照）。
2. `npm run mock` で模擬ページを起動し、http://127.0.0.1:4173/login.html を開く。

## 1. パネルを開き、調査対象を作る

1. **記録したいタブを表示した状態で**、ツールバーの TraceLens アイコンをクリックする。
   - サイドパネルが開きます。同時に、そのタブへの一時的なアクセスが許可されます（同一オリジン内の遷移まで有効）。
   - 「記録対象タブ」にページのタイトルとURLが表示されれば許可済みです。表示されない場合は、もう一度アイコンをクリックしてください。
2. 「＋ PJ」でプロジェクトを作る（例: 「勤怠システム刷新調査」）。ここでの PJ は調査のまとまりを指す TraceLens 上の単位です。
3. 「＋ シナリオ」でシナリオを作る（例: 「工数の登録」。調査目的は後からでも書けます）。

### 記録の追加設定（任意・既定は無効）

パネルの「記録の追加設定」で、次の 2 つを選べます。設定は**次の記録開始から**有効になり、記録中は変更できません。

- **操作前の画面を参照する**: 直前に取得した画像を「直前の観測時点の画面」として参照します。新しい画像は作りません。画像の取得以降に DOM・スクロール・サイズの変化を観測していない場合だけ参照します。観測の範囲で変化がないことを示すだけで、画面が同一である保証ではありません。
- **新しいタブ・ウィンドウへ記録対象を切り替える**: 対象タブから開かれたタブへ記録対象を移します（同時に記録するのは 1 つだけ）。切り替え先にアクセス権がない場合は、そのタブでアイコンをクリックすると切り替わります。

## 2. 記録する

1. 「● 記録を開始」を押す。開始時点の画面と DOM が保存されます。
2. 普段どおり操作する。模擬ページでの例:
   - 社員番号とパスワードを入力してログイン（**パスワードの値は保存されません**）
   - 対象日を入力 → PJ を選択 → 工程の候補が更新されるのを待って工程を選択 → 工数・作業メモを入力 → 保存
   - 「登録済み一覧」を開く、再読込して登録値が残っているか見る
3. 記録中にできること（どれも任意です）:
   - **直前の操作へのメモ**: パネル下部で、目的・値の種別（固定値／変数）・変数名・入力元・成功条件を書けます。一覧の別の手順をクリックすれば、その手順に書けます。
   - **いま完了を確認**: 「保存が終わった」と人間が判断した時刻を残します。
   - **画面を保存**（`Alt+Shift+S`）: 表示領域の画面と DOM を手順として追加します。
   - **ページ全体**: ページをスクロールしながら取得し、1 枚に合成します。実際の見た目と一致しないことがあります。ページ全体の取得後、元のスクロール位置へ戻します。
   - **要素を画像で保存**: ページ上の要素を選ぶと、その範囲だけを切り出して保存します（見えている部分のみ）。
   - **要素を選んで注記**: ページ上の要素をクリックして選びます。このクリックではページ側の処理（送信・遷移）は起きません。`Esc` またはパネルのボタンでキャンセルできます。
   - **一時停止／再開**: 一時停止中の操作は記録されません。
4. 「■ 終了」を押す。終了時点の画面と DOM が保存されます。

### 記録中の表示の見方

| 表示 | 意味と対処 |
|---|---|
| 「いま表示中のタブは記録対象ではありません」 | 別のタブを見ています。そのタブの操作は記録されません。 |
| 「記録が中断しています: …アクセス権がありません」 | 別オリジンへ遷移して権限が失効しました。対象タブで TraceLens アイコンをクリックするか `Alt+Shift+S` で継続します。 |
| 「記録できないページへ遷移した」 | ブラウザ内部ページなど、拡張機能が扱えないページです。 |
| 「対象タブが前面に表示されていなかったため取得していない」 | 対象タブが背面のときは画面を取得しません（他のタブの画像を混ぜないため）。 |

### うまく記録するコツ

- 操作の後、画面の変化が落ち着くのを一呼吸待つと、操作後の画面がきれいに残ります。待たずに次の操作をした場合は、次の操作の開始時点の画面が保存され、その旨が注記されます。
- ページを開き直した直後（読み込み完了前）の操作は、記録できないことがあります。
- 対象システムがログイン時などに別ドメインへ移動する場合は、移動後にアイコンをクリックし直すか、あらかじめ「アクセス権について」から全サイトへのアクセスを許可してください。

## 3. レビューする

パネルの「レビュー画面を開く（編集・再生・取り込み）」を押します（後日でも、同じブラウザなら開けます）。

- **左: 操作一覧** — 番号・種別・説明。`✎ 注記` は注記あり、`⚠ 取得失敗` は取得できなかった情報あり、`画面なし` は画面を取得していない手順です。チェックを外すと出力対象外になります（削除はされず、元の順序と時刻は保持されます）。
- **中央: 画面** — その手順の画面と、画像の取得時刻・操作時刻。橙色の枠は、取得直前に再計測した操作対象の位置です。対応を確認できない場合は枠を表示しません。画面がない手順では理由を表示し、参考として「直前の記録画面」を明示して表示します。
- **右: 意図と記録／再生設定と結果** — 「意図と記録」では目的、入力値の固定／変数、変数名、入力元、変換ルール、次へ進む条件、成功条件（根拠: 人間が記入／観測済み／未確認）、分岐・繰り返し、メモ、未確認事項を書けます。観測された通知表示（例: 「保存しました」）は、ワンクリックで「観測済み」の成功条件にできます。「再生設定と結果」は次節の再生で使います。
- **技術情報**（折りたたみ）— 要素情報、セレクター候補と一致件数、DOM、時間、取得範囲と制限。
- 「シナリオ情報」で、調査目的・前提条件・期待する最終結果・未確認事項を書けます。

### 手順の編集

- **並べ替え**: 手順の ↑ ↓ で、同じグループ内の順序を変えられます。手順をドラッグして別のグループへ移すこともできます。並べ替えは表示と再生の順序だけを変え、記録された順番（`seq`）と操作時刻は変わりません。
- **追加**: 「＋ 手順を追加…」で、待機（条件だけの手順）・クリック・入力・選択・チェック・URL への移動を人が追加できます。追加した手順は記録ではなく、`authored` として区別されます。
- **削除**: 手順を削除すると確認が出ます。元に戻せません。過去の再生結果には、削除した手順の番号が残ります。出力対象から外すだけなら、チェックを外してください。
- **グループ**: 「グループの管理」でグループを作る、名前を変える、削除する、親グループを選んで入れ子にする（循環は作れません）。削除したグループの手順は親へ移ります。

### 変数

「変数」で `{{変数名}}` を定義します（例: `工程コード`）。変数名は 1〜64 文字の文字・数字と `_ - ・ .` です。`secret` を付けた変数は既定値を保存せず、再生のたびに入力を求めます。入力された値は保存されず、拡張機能のバックグラウンドが停止すると失われます（一時停止からの再開時に再入力を求められます）。再生時の変数の値は出力 ZIP に含めません。

## 4. 再生する

「再生設定と結果」タブで、記録したシナリオを対象ページで再生できます。再生は、操作を実行し、待機条件を観測することだけを行います。**業務処理の完了や成功は確認しません。**

### 再生の準備

1. 各手順の再生設定を必要に応じて編集します（「この手順の再生設定を編集」）。
   - **値テンプレート**: 入力・選択に使う値。`{{変数名}}` を含められます。未指定なら記録された値を使います。
   - **セレクター**: 記録された候補より先に試す CSS か XPath を人が指定できます。
   - **待機条件**: 操作後に観測する条件（要素の出現・消失、文字列の表示、URL の一致、画面変化の静止）。未指定は画面変化の静止（400ms、上限 2.5 秒）です。
   - **失敗したとき**: 再生を止める（既定）／この手順を飛ばして続ける。タイムアウトは既定 10 秒です。
   - 機密欄（パスワードなど）の手順は値を入力せず、人が操作します。
2. 対象を選びます: 全体／選択した手順から最後まで／選択範囲（開始〜終了）／選択した手順だけ。
3. 「▶ 再生を開始」を押すと、開始前の確認が出ます。値が決まらない変数、人が行う手順、再生対象外の手順を一覧で示します。

### 再生の対象タブ

「再生するタブ」で、次のどちらかを選びます。

- **新しいタブ**（既定）: 計画の最初の手順（ページの移動）の移動先を、新しいタブで開きます。最初の手順が移動でない場合は、新しいタブでは開始できません（「範囲を記録開始・ページ遷移の手順から始める」か、既存のタブを選んでください）。
- **既存のタブ**: 開いているタブから選びます。候補は、アクセスが許可されたサイトのタブだけです（それ以外のタブは URL を読めないため、候補に出ません）。一覧が古いときは「タブの一覧を更新」を押してください。選んだタブのサイトへのアクセスも、開始時の許可に含まれます。

### 再生中

- 再生を開始するとき、ブラウザが対象サイトへのアクセス許可を確認します。拒否すると再生は始まりません。
- 再生はパネルの記録と同時には動かせません。
- 一時停止・再開・「1 手順実行」（1 手順ずつ進めて止める）・「■ 停止」で制御します。
- **人が行う手順**（機密欄、ファイル選択、対象要素を特定できない操作）では、再生が止まり、人が操作したあと「続行」を押すと次へ進みます。
- **入力済みの値**（記録時に、人が入力していないのに入力欄に値が入っていたもの。ブラウザの自動入力など）は、手順の種別「入力済みの値」として記録されます。再生では既定で、その時点で入っている値をそのまま使い、入力欄が空なら再生が止まって人の操作を待ちます。再生設定で値テンプレート（変数）を指定すると、その値を入力します。
- **パスワード等の機密欄**は、既定では人が入力するのを待ちます。再生設定で「secret の変数の値を入力する」を選ぶと、再生の開始時に入力した値を書き込みます（値は保存・出力しません）。機密欄に指定できるのは secret の変数だけです。
- ブラウザの自動入力は、人がページを操作するまで値をページに渡さないことがあります。その状態でログインボタンなどを押すと空の値で送信されるため、再生は操作せずに止まります（「自動入力の表示があるが、値がページに渡っていない入力欄がある」）。自動入力された入力欄を一度クリックしてから「再試行」してください。毎回止めたくない場合は、その欄に変数を指定してください。
- **失敗したとき**は、「再試行」「スキップ（人が行ったものとして先へ進む）」「停止」から選びます。
  - その手順の操作が実行された、または実行された可能性があるときは、「再試行」の前に警告が出ます。再試行すると同じ操作がもう一度行われ、登録などが二重になるおそれがあるため、対象タブの状態を確認してから「二重になる可能性を確認して再試行」を押してください。
- 別オリジンへ遷移してアクセス権を失ったときは、「アクセスを許可して再開」で続けられます。実際に足りないサイトのアクセスを求めます。タブの URL が読めず分からないときは、すべてのサイトへのアクセス（任意の権限）を求めます。操作済みの手順は、再開しても操作を繰り返さず、待機条件の観測から続けます。
- 手順の実行中に「■ 停止」を押すと、実行中だった手順は「停止時に実行中」として結果に残ります（成功にも未実行にもしません）。

### 結果の見方

各手順に次のいずれかが付きます。

| 状態 | 意味 |
|---|---|
| ok | 操作を実行し、待機条件を観測できた。業務処理の完了を示すものではない |
| failed | 失敗した。理由（要素が見つからない、一致が複数、待機条件を観測できない など）が付く |
| skipped | 再生の対象外、または人が飛ばした |
| manual | 人が行う手順 |

再生の結果は出力 ZIP の `latestReplayRun` と `scenario.md` に「再生で観測した結果」として出ます。「完了」は最後まで実行したことを示し、業務の成功ではありません。

### 再生の制限

- 再生は `isTrusted` でないイベントを使います。信頼されたイベントだけに反応するページでは、操作が効かないことがあります。
- alert・confirm で止まると、ページから応答がなく失敗になります。
- クロスオリジンの iframe は、そのオリジンのアクセス権が必要です。
- 操作の後に遷移した先の待機条件は、遷移後のページに権限がある場合だけ観測できます。
- **記録した再読み込み**は、フォームの再送信（重複登録）を避けるため、現在の URL へ GET で移動し直して再生します。ブラウザの再読み込みとは異なり、POST の内容や一時的な状態は再現しません（手順の「注記」に出ます）。URL の `#` 以降は外します。

## 5. 取り込み

「取り込み…」で、手順を別のシナリオから、または出力 ZIP から取り込めます（記録中のシナリオへは取り込めません）。

- **別のシナリオから**: 手順を選んでコピーします。取り込み先のグループを指定できます。
- **出力ZIPから**: 出力された ZIP を読み込みます。取り込んだ内容は調査データで、TraceLens は内容（セレクター・値・待機条件など）の正しさを検証していません。再生する前に確認してください。置換前の値は ZIP にないため復元されません。

取り込んだ手順の時刻は、取り込み元の観測時刻を `importedFrom` に残し、取り込んだ時刻とは別に扱います。

## 6. プロジェクト・シナリオの管理

「管理…」で、プロジェクト名を変えられます。プロジェクトとシナリオは削除できます。削除は「完全に削除する」を選んだときだけ行われ、元に戻せません（シナリオを削除すると手順・画像・再生結果も消えます）。シナリオ名は、レビュー画面のシナリオ情報で変更できます。

## 7. 出力前の確認と ZIP 出力

「AI向けZIPを出力…」を押すと確認画面が開きます。

1. **入力値の置き換え** — 元の値と置き換え後の文字列（例: `{{工程コード}}`）を指定します。手順書・JSON・DOM のすべてに同じ置換が適用されます。記録された入力値のボタンからも追加できます。
   - **正規表現のルール**: 「＋ 正規表現のルールを追加」で指定します。フラグは `i` `m` `s` `u` のみ使えます。`replaceWith` は常に文字どおりの文字列で、`$1` などの参照は展開されません。繰り返しの入れ子（`(a+)+`）や後方参照（`\1`）は使えません。適用できないルールは理由を表示します。
2. **画像の確認** — 実際に出力される画像が並びます。**画像内の文字は自動では処理されません。** 必要なら「塗りつぶす」から画像の編集に入ります。
   - **塗りつぶしを追加**: 矩形を黒で塗りつぶします。
   - **ぼかしを追加**: 矩形を粗いモザイクにし、元の文字を読み取れなくします。元の画素は復元できません。
   - **切り抜き範囲を指定**: 範囲の外側は出力に含まれません。「切り抜きを解除」で元に戻せます。
   - 編集は出力画像にだけ適用され、保存済みの原本は変わりません。不要な画像は「出力から除外」できます。
3. **出力内容のプレビュー** — ファイル一覧と内容を確認します。置換前の値が残っていないかの検査結果も表示されます。
4. 「ZIPを出力」で `tracelens-export_日時.zip` を保存します。

ZIP の中身は [data-format.md](data-format.md) を参照してください。`implementation-request.md` の【 】を記入し、ZIP と一緒に実装担当の AI に渡します。

## 8. 注意

- 手順を出力対象外にしても、同じ値が他の手順の DOM に残ることがあります。値を消したい場合は置換を使ってください。
- 記録データはブラウザのプロファイル内に保存されます。拡張機能を削除すると記録も削除されます。必要なものは ZIP に出力しておいてください。
- 再生は対象のページで実際に操作します。業務データを変更する操作を再生する前に、テスト環境であることと、再生の範囲を確認してください。
- UI は日本語（既定）と英語を切り替えられます（サイドパネルとレビュー画面のヘッダー）。出力 ZIP、保存データ由来の文言（通知・理由・制限など）、ページ内の再生中表示は日本語のままです。
